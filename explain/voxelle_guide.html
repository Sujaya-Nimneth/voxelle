1.5 Technical Interview Q&A Cheatsheet

Use these prepared responses for technical interviews or peer code reviews:

Q1 Why did you choose the browser Web Speech API over Whisper or ElevenLabs?
"Two main reasons: latency and accessibility. Cloud speech APIs require uploading audio buffers over WebSockets or HTTP, introducing network roundtrips, encoding overhead, and continuous API costs. Web Speech runs natively on the client's audio hardware with zero latency and zero billing. Plus, it allows any reviewer to run the repository with zero configuration. Because the voice layer is isolated in custom React hooks (useSpeechRecognition and useSpeechSynthesis), swapping to a server-side WebSocket stream or WebRTC to Gemini Live is a clean drop-in replacement."
Q2 How do you handle Next.js SSR hydration mismatches with browser-only APIs?
"APIs like window.SpeechRecognition and window.localStorage do not exist on the server. If a component attempts to read them during server-side pre-rendering, Next.js throws a hydration mismatch error. We resolved this through three safeguards:
1. Checking typeof window === 'undefined' guards.
2. Initializing component state with safe defaults, then hydrating from localStorage inside a client-side useEffect with a hydrated boolean flag.
3. Adding suppressHydrationWarning to the RootLayout body."
Q3 How does Voxelle prevent acoustic feedback loops between STT and TTS?
"A common bug in voice assistants is the microphone picking up the speaker's own voice, creating an infinite conversation loop. In useAssistant.ts, we enforce strict state transitions and synchronous execution locks:
1. When the assistant enters the speaking state, the speech recognition instance is aborted.
2. When the user initiates voice input via startListening(), any active speech synthesis is immediately halted via window.speechSynthesis.cancel().
3. A synchronous processingRef.current boolean guard prevents duplicate submissions while async requests are in flight."

2.2 The Central Orchestration Brain (`useAssistant.ts`)

Located at src/hooks/useAssistant.ts, this 400-line hook serves as the application's central nervous system. It connects the user interface, speech input, speech output, backend API, tool lifecycle, and persistent storage.

The 4-State Finite State Machine

The assistant transitions through four distinct states, represented by the union type AssistantStatus = 'idle' | 'listening' | 'processing' | 'speaking':

┌───────────────────────────────────────────────────────────┐ │ IDLE │ └───────────────┬───────────────────────────▲───────────────┘ │ User taps Mic │ TTS completes or │ or speech detected │ Mute clicked ▼ │ ┌───────────────────────────┐ TTS Voice │ │ LISTENING │ Response │ └───────────────┬───────────┘ │ │ Final transcript detected │ ▼ │ ┌───────────────────────────┐ API JSON │ │ PROCESSING │───────────────┤ └───────────────┬───────────┘ (No audio) │ │ API returns text + TTS │ ▼ │ ┌───────────────────────────┐ │ │ SPEAKING ├───────────────┘ └───────────────────────────┘

Synchronous Concurrency Protection with React Refs

In React, useState updates are queued asynchronously. Because browser speech events (like onresult followed immediately by onend) can fire milliseconds apart, using standard state flags alone leads to duplicate API submissions.

To resolve this, useAssistant pairs state with synchronous useRef locks: 

// Synchronous locks to prevent double-dispatch race conditions
const statusRef = useRef<AssistantStatus>('idle');
const processingRef = useRef(false);

const processMessage = useCallback(async (userText: string, image?: string | null) => {
  // Guard clause: immediately reject duplicate triggers synchronously
  if (processingRef.current) return;
  processingRef.current = true;

  try {
    setStatus('processing');
    // ... API call, tool execution, TTS triggering ...
  } finally {
    processingRef.current = false;
  }
}, [/* dependencies */]);

2.3 Voice Engineering Pipeline (STT & TTS)

1. Speech-to-Text: `useSpeechRecognition.ts`

This custom hook encapsulates browser voice recognition. Key engineering considerations include:

  • TypeScript Global Interface Augmentation: Web Speech types are not in standard TypeScript DOM declarations. The hook defines custom interfaces for SpeechRecognitionInstance, SpeechRecognitionEvent, and extends the Window interface.
  • Automatic Intent Submission on Final Transcript: The hook listens for result.isFinal and extracts the trimmed transcript, automatically waking the processing pipeline without requiring the user to press a submit button.
  • Error Classification: Distinguishes intentional user cancellations (aborted) from actual hardware issues (not-allowed, audio-capture, no-speech).

2. Text-to-Speech: `useSpeechSynthesis.ts`

Wrapping window.speechSynthesis, this hook manages vocal output:

  • Cross-Browser Voice Population: Chrome loads voices asynchronously and triggers a voiceschanged event, while Safari loads them immediately. The hook implements a dual-check listener to guarantee available voices are always registered.
  • Natural Voice Heuristics: Automatically searches available voices for high-quality accents (e.g. "Google Natural", "Samantha", "Daniel", "Serena") before falling back to default system engines.
  • Clean Audio Interruption: Calls window.speechSynthesis.cancel() before any new utterance, guaranteeing audio tracks never collide or overlap.

2.4 Multi-Provider AI Engine & Function Calling (`/api/chat`)

The server route at src/app/api/chat/route.ts inspects the AI_PROVIDER environment variable to dynamically delegate work:

Provider 1: Google Gemini 2.0 Flash (`AI_PROVIDER=gemini`)

Directly targets the Google Generative Language API endpoint. It formats conversation history into Gemini's user and model roles, injects base64 image data into inline_data parts, and passes toolDefinitions into tools.function_declarations.

Provider 2: Groq Cloud Llama 3.3 (`AI_PROVIDER=groq`)

Connects to Groq's low-latency OpenAI-compatible endpoint using llama-3.3-70b-versatile. It translates tool definitions into standard OpenAI JSON function schemas and parses returned tool_calls.

Provider 3: Offline Mock Engine (`AI_PROVIDER=mock`)

The default zero-configuration mode. Uses intelligent keyword pattern matching (in src/app/api/chat/tools.ts) to match user intent against calendar bookings, smart home controls, and ambient workspace queries—enabling full demonstrations without any API keys.

2.5 Multimodal Vision Pipeline (`ImageDropzone.tsx`)

The image dropzone component allows users to attach diagrams, UI mockups, or photographs:

1
File Ingestion
react-dropzone validates drag-and-drop or picker events against allowed image MIME types (PNG, JPG, WEBP, GIF) with a 10MB file limit.
2
Client-Side Base64 Conversion
The browser's native FileReader.readAsDataURL(file) encodes the file into a base64 Data URI, bypassing the need for temporary cloud storage buckets.
3
Multimodal Payload Construction
In route.ts, a regular expression extracts the MIME type and raw base64 data string, constructing an inline_data part for Gemini 2.0 Flash to process in parallel with the user's voice prompt.

2.7 Reliability, Resilience & Edge Cases

Several production resilience mechanisms are built directly into Voxelle:

  • Diagnostic Warning Overlay (PermissionWarning.tsx): Automatically alerts users if microphone permissions were denied or if the browser lacks Web Speech support, providing direct remediation instructions.
  • LocalStorage Synchronization: Chat history and recent signals automatically persist in the browser and safely hydrate without causing SSR mismatches.
  • Dynamic Tool Timeout & Auto-Dismissal: Tool execution cards automatically display a progress shimmer bar for 1.2s during execution, switch to a completed state, and self-dismiss after 6 seconds to keep the workspace clean.
